# Stick-Figure Video Pipeline — Handover Guide

**What this is:** a fully local, $0 pipeline that turns a written idea into a finished narrated,
animated MP4. Nothing is generated by an image or video AI model — every frame is drawn by code
and screenshotted, so there is no API key, no quota, no watermark and no per-video cost.

**Verified on:** Windows 11, Git Bash, 16 GB RAM, RTX 4060 Laptop 8 GB, Node 24, ffmpeg 9.0.1.
**Measured results:** 29.9 s @ 1080p rendered in 84 s; 13.6 s @ 1080p rendered in 41 s.
10.8 s @ 1080p 9:16 with narration, music and 16 foley cues: 26 s render, ~55 s end to end.
**Last updated:** 2026-11-08.

## 0. The one thing to understand before you start

The pipeline has two halves and they are not the same kind of thing.

| Half | What it is | Who/what does it |
|---|---|---|
| **The renderer** | deterministic code: draw frame → screenshot → encode | commands you can run yourself |
| **The director** | decides *what* to draw and writes that as JavaScript | **a coding agent — not you, not a script** |

The renderer cannot invent a video. It executes scene code. Historically someone had to write
`scenes/shots/*.js` by hand — that was the step that needed a language model with file-editing and
terminal tools.

**That step is now automated.** `tools/director.py` is a deterministic template compiler: it turns a
story JSON into a complete project — cast, blocking helpers, a parametric set, and one file per shot.
No AI, no network, no randomness. Any tool, or no tool at all, can produce the JSON.

### 0.1 One command

    python tools/generate.py --story story.json --out projects/my-video --audio

| stage | what it does |
|---|---|
| `director.py` | story JSON → `cast.js`, `blocking.js`, `sets/room.js`, `scenes/shots/*.js` |
| `narrate.py` | Kokoro TTS → `build/voice.wav` + `timeline/words.json`, and **retimes every shot to its measured speech** (a shot lasts as long as its line, not a fixed grid) |
| `sound_design.py` | whoosh on every hard cut, footsteps on walks, riser into flash/zoom, ambience bed |
| `render_gate.py` | runs `render.mjs` and **hard-fails on any shot error** — `render.mjs` itself exits 0 even when a shot throws |
| `mix.py` | music + sfx + loudness normalise (−14 LUFS) + mux |
| `review_frames.py` | frames + a checklist for the review only eyes can do |
| `seam_gate.py` | does anything carry across each cut? `--auto` honours a declared `cut_intent` |
| `render_report.py` | written report: format, loudness, motion, style lock, approval state |

`--strict` fails the run on a dead cut. Drop `--audio` for a silent render.

A hand-written project can still beat the compiler — `projects/one-more-night-9x16/` is the reference
for what "good" looks like, and it was written by hand. Use it as the bar, not as the input format.

## 4. STOP YOUR LOCAL LLM BEFORE EVERY RENDER — non-negotiable

This is the single most common failure and it is not obvious.

```bash
# check commit headroom in Git Bash
powershell -NoProfile -Command "'commit_avail_GB: ' + ('{0:N1}' -f (Get-CimInstance Win32_OperatingSystem).FreeVirtualMemory/1MB)"
```

You need **at least ~6 GB of commit headroom**. Measured on this machine: a running `llama-server`
holding a 15 GB GGUF reserves **26.56 GB of commit address space** while using almost no physical
RAM, which leaves ~2.6 GB and makes ffmpeg and MKL fail with `Cannot allocate memory` /
`mkl_malloc: failed to allocate memory`. The renderer's own `setup.sh` mislabels that as
"model download FAILED" — it is not a download problem.

**Rule: unload/stop the model server → render → then reload it.** Never both at once.

## 5. Making a video — the flow

All commands run from `~/video-studio/aitrends-2d-studio`. Set a shorthand first:

```bash
STUDIO=~/video-studio/aitrends-2d-studio
FH=~/video-studio/faceless-shorts
PY=~/.faceless-shorts/venv/Scripts/python.exe
cd "$STUDIO"
```

### Step 1 — Write the script

Two options:

- **Ask your agent** (needs internet or a local coding model): give it the topic, the length in
  seconds, and the tone. Expect ~2.8 spoken words per second (30 s ≈ 85 words).
- **Write it yourself.** One line per *cut*, not per sentence. A line is what the picture changes on.

Save the plain narration as `script.txt`, one line per cut.

### Step 2 — Generate the voiceover (offline, free)

Single voice — reuse the timing project's format:

```bash
mkdir -p ~/faceless-shorts/vo && cd ~/faceless-shorts/vo
# put a script.json in there (see faceless-shorts/SKILL.md §1 for the schema), then:
"$FH/scripts/py" "$FH/scripts/voice.py" .
# -> data/narration.wav  +  data/lines.json
```

**Two or more voices (dialogue)** — use `voice2.py`, which speaks each line in its own voice:

```bash
mkdir -p ~/faceless-shorts/vo2 && cd ~/faceless-shorts/vo2
# write dialogue.json:  { voice, speed, lead, outro, gap,
#   lines: [ { who:"RAE", voice:"af_heart", text:"...", gap:0.28 }, ... ] }
"$PY" "$FH/scripts/voice2.py" .
# -> data/narration.wav, data/lines.json, data/script.txt
```

Voices that narrate well: `am_michael` (steady US male, default), `am_puck` (lively), `af_heart`
(warm US female, best overall), `af_nicole` (soft), `bm_george` (UK documentary), `bf_emma` (UK calm).
Full list: `"$FH/scripts/py" "$FH/scripts/voice.py" --list`

### Step 3 — Create the project and align word timings

```bash
"$PY" tools/new_project.py --name <slug> \
    --voice  "C:/Users/<you>/faceless-shorts/vo2/data/narration.wav" \
    --script "C:/Users/<you>/faceless-shorts/vo2/data/script.txt" \
    --aspect 16:9 --resolution 1080p --title "<Title>"

"$PY" tools/transcribe.py --project projects/<slug> \
    --script projects/<slug>/input/script.txt --lang en --model small
```

The transcribe line prints an alignment percentage. **It must be ≥ 90 %.** If it is lower, your
`script.txt` does not match the audio — fix the text and re-run.

Then get the beat sheet:

```bash
"$PY" tools/beats.py --project projects/<slug>
```

This writes a draft `story/shots.json` where every shot's `scene` field says `"TODO"`.

### Step 4 — Direct it (this is the agent's job)

Four files get written or rewritten. Read these first, in this order:

1. `../plugin/skills/make-2d-video/references/style-bible.md` — the look. Read it fully.
2. `../plugin/skills/make-2d-video/references/story-breakdown.md` — how to write the shot list.
3. `../plugin/skills/make-2d-video/references/engine-api.md` — the API you must code against.
4. `examples/reaction-time/scenes/` — copy its idiom; it is the only known-good example.

Files you produce:

| File | Contents |
|---|---|
| `story/shots.json` | one entry per shot: `id, start, end, line, scene, set, bars, in:{type}, sfx[]` + a `music` list |
| `scenes/cast.js` | one outfit object per recurring character; **signature colour never changes** |
| `scenes/sets/<name>.js` | reusable environments, anchored to `GY` (ground) and `CX` (centre) |
| `scenes/shots/main.js` | `registerShot('s001', { draw(g,t,info){…} })` per shot |

Hard rules from the bible that people break first:

- **No static shots.** Every shot needs a camera move: `z: 1 → 1.06`, lateral `x`, `roll`, or `shake`.
- **Rim light on every lit figure** — `rim: { color: M.rim, dir: [dx,dy], w: 4 }`. Without it, black
  figures vanish into dark sets.
- **Atmosphere in nearly every shot** — `FX.dust`, `FX.rain`, `FX.godRays`, `FX.lensStreak`.
- **15–25 shots per minute.** A 30-second video wants 8–12 shots, not 2.
- **No `Math.random()` / `Date.now()`** — use `rng(seed)`. They break determinism between frames.
- Valid names only (an invalid one throws and you lose the render):
  - styles: `dusk, midnight, golden, neon, storybook`
  - moods: `day, dusk, golden, midnight, night, storm, storybook, void`
  - music moods: `mystery, tension, action, wonder, hopeful, sad, triumph, playful, calm, dark, epic`
  - expressions (18): `neutral, happy, joy, smile, surprised, shocked, scared, worried, nervous,
    angry, determined, sad, cry, smirk, sleepy, thinking, confused, awe`
  - poses (27): `stand, relaxed, talk, explain, point, pointUp, wave, cheer, handsOnHead,
    crossArms, think, shrug, holdFront, phone, reach, sad, facepalm, ready, crouch, sit, sitBack,
    kneel, lie, dive, kick, jump, fall`
  - sfx: `whoosh swish impact hit riser slowmo freeze tick clock heartbeat pop blip counter ding
    shimmer stinger flash glitch hum city rain wind thunder carpass footstep phonering phonebuzz
    murmur cheer applause powerup kick`
- **Gradient stops are `[offset, colour]`**, not `[colour, offset]`. Swapping them gives
  `addColorStop ... non-finite`.

Set the style:

```bash
"$PY" -c "import json;p='projects/<slug>/config.json';c=json.load(open(p));c['style']='midnight';json.dump(c,open(p,'w'),indent=1)"
```

### Step 5 — QC the frames BEFORE rendering

```bash
node render.mjs --project projects/<slug> --sheet --scale 0.5
```

Read every `SHOT ERROR` line and fix it. Then **open `projects/<slug>/build/sheets/sheet_01.png`
and actually look at it.** For each frame ask:

- Does it make sense? One visual mode per shot.
- Does the picture match the words being spoken at that exact second?
- Is anything colliding with a label or the caption zone?
- Did any character change pose, outfit or screen direction between shots? (continuity)

Fix, re-render the sheet, look again. Rendering is slow; looking is free. **Never skip this.**

### Step 6 — Render and mix

```bash
node render.mjs --project projects/<slug>          # long; prints fps and ETA
"$PY" audio/mix.py --project projects/<slug>       # music + sfx + duck, −14 LUFS, muxes MP4
```

Output: `projects/<slug>/out/<Title>.mp4`

### Step 6b — Dead-frame check (merged tool, see §12)

```bash
"$PY" tools/motion_audit.py projects/<slug>/out/<Title>.mp4
```

Exits 1 on a genuinely dead stretch. **It does not judge whether the video feels alive** — read
`docs/MOTION_BASELINE.md` before you trust it for anything else.

### Step 7 — Verify the deliverable

```bash
f=projects/<slug>/out/*.mp4
ffmpeg -i $f 2>&1 | grep -E "Duration|Stream"
ffmpeg -v info -i $f -af volumedetect -vn -f null - 2>&1 | grep mean_volume
```

Expected: correct duration, an `Audio` stream present, `mean_volume` between about −20 and −15 dB.
A silent or missing audio stream means `mix.py` failed — check the music mood and sfx names.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `mkl_malloc: failed to allocate memory` | commit headroom exhausted — your LLM server is loaded | stop `llama-server`, verify ≥6 GB commit avail, re-run |
| `ffmpeg: ff_frame_thread_encoder_init failed` / `Cannot allocate memory` | same cause, different face | same fix. Do **not** re-download models; they are cached |
| `setup.sh: whisper model download FAILED` | misleading label — the model is cached, the *load* failed | check commit headroom first |
| `addColorStop ... non-finite` | gradient stops written `[colour, offset]` | swap to `[offset, colour]` |
| `r is not defined` / `X is not defined` in a shot | constant declared inside a `layer()` callback but used outside | hoist it above the callback |
| `poly is not defined` / `wordTime is not defined` | missing from the `import { … } from '/engine/core.js'` list | add the name to the import |
| `KeyError: 'curiosity'` in `mix.py` | invented music mood | use only the 11 valid moods in §5 Step 4 |
| `SHOT ERROR` naming an expression/pose | invented name | use only the 18 / 27 valid names |
| Alignment below 90 % | `script.txt` ≠ what the audio says | fix the text; re-run `transcribe.py` |
| Character floats, no shadow | `y` not on `GY` | put figures on the ground line |
| Subject cropped in 9:16 | shot designed for 16:9 | re-check with `--sheet` in 9:16; wides need vertical stacks |

## 8. What this pipeline genuinely cannot do

Stated plainly so nobody wastes a week:

- **No photorealistic humans.** The figures are cylinders, spheres and 11-point line rigs. A
  photoreal human needs an artist-authored mesh with skin textures — code cannot invent a face.
- **No finger articulation.** `finger` is one angle (index raised). You cannot make a character hold
  up two fingers.
- **No real neck rotation.** "Head turn" means offsetting the `head` point in a copied pose — a lean,
  not a rotation. It breaks in close-up.
- **No viseme lip-sync.** `talk` is one amplitude value driving a mouth shape, not phonemes.
- **No live-action or product footage.**
- The ceiling is "a stick-figure film lit by a cinematographer" — which is exactly what it does well.

## 9. Offline / no-internet status

| Stage | Offline? |
|---|---|
| Script writing | **No** — needs an LLM (cloud, or a local model via an agent that supports a local endpoint) |
| Voice (Kokoro) | Yes |
| Word timing (Whisper) | Yes |
| Scene code | **No** — needs a coding LLM |
| Render | Yes — zero network calls in the renderer |
| Music / SFX / mix | Yes |
| Upload to YouTube | No |

Internet is required **once**, for §3. After that the only network dependency is the intelligence in
steps 1 and 4.

**Known gap on this machine:** Python's `torch` is a CPU wheel (`2.11.0+cpu`,
`cuda.is_available() == False`) even though an RTX 4060 with driver 616.92 is present. That does not
affect this pipeline (it uses ONNX/CPU and Chrome), but it blocks any diffusion or face-animation
model. Fixing it means installing a CUDA build of torch — a deliberate dependency change, not an
accident.

## 11. Monetisation notes (why the output looks the way it does)

- YouTube requires AI disclosure only for content that **seems realistic**. Fully animated code-drawn
  video is explicitly exempt — no label needed, and this pipeline embeds no C2PA/SynthID, so nothing
  gets auto-labelled.
- YouTube's **inauthentic content** policy demonetises "AI-generated content made with generic or
  unoriginal templates giving the impression of mass production" and "characters put in the same
  situation over and over with the same outcome". A high-volume template mill is the named violation.
  Distinct storylines per episode are the named safe pattern.
- YPP thresholds: 1,000 subs + 4,000 watch hours **or** 10M Shorts views. **From 1 Feb 2027 new
  applicants need 8,000 hours or 20M Shorts views.**
- Instagram Bonuses are not available in India; Subscriptions need 10,000 followers; slideshows and
  static-image sequences are explicitly non-monetisable formats.
- Verify every factual claim against a real source before publishing. The pipeline will happily render
  a wrong fact with total confidence.

### Rejected, with reasons

- **The `stickman` engine entirely** — `chars.js` + `motion.js` + `props.js` total **114 lines**
  (`drawPerson`, `personRim`, `actor`). Ours is ~12,700 lines with 27 poses, 18 expressions, parallax,
  atmosphere, rim light and freeze-frames. It is a downgrade, so it stays out.
- **Upstream motion thresholds 0.2 / 0.3 with frozen sub-threshold 0.05** — measured on our own
  footage, our entire range is 0.0009–0.0104. Those floors sit ~60× higher and would fail every video
  we make. Replaced with 0.0006 / 0.0004 derived from our data.
- **The "is it static?" use case for the audit** — this is the important one. Ranking five of our own
  renders put the two the owner called *static* **above** the cinematic ones, and it stayed that way
  under contrast normalisation and under Farneback optical flow. Change rate is not liveliness: a
  caption pop is a big discrete change, a slow camera push with breathing and dust is a small
  continuous one. The tool ships as a dead-frame detector only, and says so in its own docstring.
- **kaomei's Gemini/Omni Flash prompt pipeline, cloud TTS default, and mandatory Google Search voice
  casting** — all break offline, $0, or unlimited. Their stickman look is the thing we are leaving.
- **Spine / DragonBones / MakeHuman / Godot / Mixamo** — GUI authoring, binary assets, and non-MIT
  licence text (`LicenseRef-LICENSE`, AGPL, CC BY). Wrong foundation for a decade-long series.
